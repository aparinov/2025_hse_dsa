Платформа двусторонняя: есть преподаватели, которые могут создвать проекты, и студенты, которые могут принимать участие в проектах. В идеале сделать два раздельных клиента, но можно подумать и о более простом решении.


Наша цель - склепать быстрый MVP сайта, который будет адекватно выглядеть, иметь базу данных и весь основной функционал
Для начала давай доуточним все необходимые вводные перед тем, как приступать к работе

заявки со стороны руководителя проекта (по умолчанию преподавателя или сотрудника внешней компании)

## Продукт и Бизнес-логика
1) После завершения проект уходит в архив, пусть это будет отдельная лента (все активные проекты vs мои проекты vs архивные проекты). Карточка проекта должна сохраняться
2) Давай пока предположим, что проекты все однотипные, кастомизацию продумаем потом
3) Давай пока предположим, что все авторизуются через платформу университета. Эта интеграция скорее всего будет непростой частью нашего проекта, для MVP опустим этот момент. Но будем иметь в виду
4) Проекты создаются преподавателями, участвовать могут студенты. Студент не может быть руководителем проекта
5) Контрольные точки - это просто текстовый список. Уведомления, даты и тд пока опустим

## Пользователи и Роли
1) Делаем один клиент с разными ролями, разные роли = разные доступы
2) Про роли:
Студент:
Видит все проекты
Может подавать заявки
Может редактировать только свой профиль
Не может создать свой проект
Не может приглашать никого в проект

## Преподадаватель-руководитель:
Может создавать/редактировать/архивировать только свои проекты
Видит заявки только на свои проекты
Может просматривать профили студентов, подавших заявку
Может искать студентов по интересам/навыкам и смотреть их профили, но НЕ может приглашать их в проект

Решать спорные вопросы, банить пользователей, видеть всю статистику и тд будем мы через админку


## Технические детали и Ограничения
1) В первый год ожидаем 200-2000 пользователей
2) При авторизации получаем ФИО, email, группа, курс, статус "студент" / "преподаватель". Для MVP делаем регистрацию по email+pass
3)Мы предоставим студентам готовый список тегов/интересов (например, "Machine Learning", "Data Analysis", "Web Development"), из которого они могут выбирать. Свои теги вводить нельзя
4) Для бейзлайна берем рекомендательную систему по тегам, дальше попробуем более сложные решения
